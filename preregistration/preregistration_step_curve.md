# Pre-registration: adaptation-step curve, LR axis, fog mechanism

Written 2026-10-18, before any run at steps {2,3,5} or at lr {1e-4, 3e-4}.
Existing results consulted while writing: the 1-step and 10-step endpoints
(pertype_*, cm_*, s10_*, oracle_s10_*), and the 1-step ACDC-fog per-class /
per-image confusion analysis (GT-sky→building 11.9% vanilla → 26.0% PDA@1;
sky IoU drops in 100/100 images).

## Design
- Checkpoint `runs/tcpr_deeplab_pdaonly/best.pth`, DeepLabV3+/ResNet-50. Config is
  identical to the existing s10 runs (bn affine, bs 2, clean_final, K=4, threshold 0.45,
  crop 512x1024), seed 0. Only `--n_adapt_steps` / `--lr_pda` change.
- Methods: PDA, TENT, supervised reference (oracle, transductive, never a method).
- Step axis: s ∈ {1,2,3,5,10} at lr 1e-3. s=1 and s=10 are the existing runs; {2,3,5} are new.
- LR axis: s=1 at lr ∈ {1e-4, 3e-4} (1e-3 exists), for all three methods.
- Populations: all 95 Cityscapes-C conditions (no subset selection), the 7 real
  adverse conditions, and the BDD-clear probe (reported separately, never pooled).
- Disclosed asymmetry: the existing 1-step synthetic PDA runs were unseeded (seed
  spread ≈0.1 mIoU); all new runs are seeded.

## Primary statistic
For each method m and setting s: refit benefit ~ vanilla mIoU (OLS, all 95, nothing
excluded), then compute the mean residual over the 7 adverse conditions = shortfall(m,s).
Also report mean synthetic benefit(m,s) and mean real benefit(m,s).

## Predictions (falsifiable; reported whichever way they land)
- P1. shortfall(m,s) < 0 for PDA and TENT at every s ∈ {1,2,3,5,10}, with ≥6/7 adverse below trend at each s.
- P2. Synthetic vs real divergence: for PDA and TENT, mean synthetic benefit at s=5 ≥ (its s=1 value − 0.5),
  while mean real benefit at s=5 < its s=1 value.
- P3. Supervised reference: mean real benefit is non-decreasing in s (tolerance 0.3 mIoU between adjacent steps).
- P4. Stopping point (iWbd). (a) Deployable: choose one s per method by maximising mean SYNTHETIC benefit only;
  the real shortfall at that s is < 0. (b) Upper bound: per-condition best s chosen with labels, applied
  symmetrically (synthetic trend refit on each synthetic condition's own best-s benefit); the real shortfall
  is still < 0. (b) uses labels and is never presented as deployable. It is the same best-iterate selection
  we criticise in the DUA reference code, so it must carry that caveat.
- P5. LR axis: shortfall < 0 at lr 1e-4 and 3e-4 for PDA and TENT. Magnitude is expected to shrink with lr
  (both benefit and prediction shrink); no prediction about magnitude.
- P6. Fog mechanism: on ACDC fog, the GT-sky→building rate (per-image CMs) is non-decreasing in s for PDA
  and TENT. On synthetic fog severity 3 (matched vanilla 59.1 vs ACDC 58.3), sky IoU does not fall more
  than 2 points below vanilla at any s ≤ 5. (Synthetic per-class from `per_class_iou`; per-image CMs are
  unavailable in multi-severity mode.)

## Objective trace
All new runs log `mean_loss_trace` (pre-update loss at each step, averaged over batches). The claim
"the objective descends while accuracy collapses" is stated only if the trace descends on real
conditions whose mIoU falls with s.

## Qualitative strip (selection fixed now)
ACDC fog val, eval order, indices 14 / 42 / 51 = the 25th / 50th / 75th percentile of per-image
sky-IoU drop under PDA@1 (−9.6 / −15.1 / −21.0). Panels: input, GT, vanilla, PDA@1, PDA@10, TENT@10,
supervised@10. Predictions come from the same eval pass as the reported metrics (`--save_preds`).
Each strip run's mIoU must reproduce its published value; otherwise the strip is not used.

## Addendum (2026-10-18, before Cityscapes-C v2 generation): seeded regeneration

**Why.** The cluster copy of Cityscapes-C (v1) was deleted for disk space, and no backup exists.
v1 was generated by `generate_cityscapes_c.py` with no seed across a 64-process pool, in two runs
(job 39338769 cancelled partway, job 39344553 resumed and kept its files). Its 11 stochastic types
(gaussian/shot/impulse/speckle noise, glass/motion blur, fog, frost, snow, spatter, elastic) cannot
be reproduced. Its 8 deterministic types (brightness, contrast, saturate, jpeg_compression, pixelate,
defocus/zoom/gaussian blur) should be reproducible within a fixed software environment.

**v2 seeding scheme** (`scripts/generate_cityscapes_c_v2.py`). **SEED0 = 20261018**.
seed = `SeedSequence([SEED0, img_idx, TYPE_IDX[corruption], severity]).generate_state(1)[0]`, set via
`np.random.seed(seed)` *and* passed as `rng=seed` to `skimage.util.random_noise` (impulse_noise; it
ignores the global RNG in scikit-image ≥0.19) immediately before each `corrupt()` call. img_idx is the
image's position in sorted(city)/sorted(filename) order over `leftImg8bit/val`; TYPE_IDX is its position
in `imagecorruptions.get_corruption_names("all")`. The set is order-independent and parallel-safe, and any
single image can be regenerated alone. Each per-type job writes `MANIFEST_seeds_<type>.csv` (seed + sha256 per output; generation runs as 19 parallel per-type jobs, which the per-item seeding makes equivalent to one run) and
`MANIFEST_env.json` (pinned versions). A built-in self-check regenerates 20 random items per type (380 total) in shuffled order in a
fresh pool and requires byte-identical PNGs, failing the run otherwise.

**Environment pinned** (in `MANIFEST_env.json`): imagecorruptions 1.1.2, numpy 2.0.1, scikit-image 0.25.2,
scipy 1.15.3, Pillow 12.2.0 (plus its libjpeg/zlib versions), opencv-python 5.0.0.93, Python 3.10.
v1's July environment was not recorded; if the gate fails on JPEG/pixelate, codec drift is the first suspect.

**Validation gate (pre-specified; must pass before any adapted v2 run).** Vanilla mIoU on the 8 deterministic
types × 5 severities (40 conditions) of v2 must reproduce the published v1 `pertype_vanilla_*` values within
|Δ| ≤ 0.05 mIoU on the same GPU class. The published runs were H200; on another class, the measured
cross-GPU vanilla drift (≤0.01) is reported alongside. **Any miss → stop and debug; do not proceed.**

**Reporting split (no silent swap).** The submission's Tables 1–3 stay on v1. The step curve is a new experiment on v2
with its own refit trend and its own re-run endpoints (steps 1 and 10) for every method, on one GPU type per method.
Reported without prediction: the distribution of |Δ vanilla mIoU| v1→v2 over the 55 stochastic-type conditions,
and the shift in the v2 fit (slope, R², shortfall) relative to v1. Camera-ready may unify only if the v2 endpoints
match v1 within noise.

**Sky→building scope check (before any prose).** Using existing 1-step per-image CMs, compute the GT-sky→building
rate (vanilla vs PDA/TENT/DUA) on ACDC night, rain and snow, plus BDD and Foggy Zurich. If ≥3 adverse conditions
show an increase of ≥5 points under PDA, describe it as a pattern; otherwise describe it as fog's diagnostic case.
Optional correlate: per-image sky-vs-building luminance contrast vs sky-IoU drop.

**Gate log (2026-10-18).** V100 gate run first (`csc_v2_gate_v100.json`): 40/40 deterministic conditions within tolerance,
max |Δ| 0.015, mean 0.003 → PASSED. The stochastic-type v1→v2 shift over 50 of 55 conditions (glass_blur pending):
|Δ| median 0.17, mean 0.23, p90 0.47, max 0.87 mIoU. *Deviation, by user decision at ~21:10:* the H200 drainers were
released on the V100 gate under the other-GPU-class clause rather than waiting about 1 h for the H200 gate (unit 05 runs
zoom_blur last). The H200 gate still runs and overwrites `csc_v2_gate_h200.json`. If it fails, new adapted runs stop
(`conc.txt` = 0) and any H200 results already produced are reported as gate-failed.
**H200 gate (binding; run 2026-10-18 ~22:48 on a CPU node from unit 05's vanilla, because unit 05 exited after its last
vanilla type without running the gate step):** 40/40 deterministic conditions within tolerance, max |Δ| 0.019, mean
0.005 → PASSED, which confirms the earlier V100-based release. On the same GPU class the real-suite vanilla reproduces
v1 exactly (0.000), so the ≤0.019 here reflects pixel-level differences in the regenerated deterministic images
(likely codec/library drift since July), not GPU noise. Stochastic types, all 55 conditions: |Δ| median 0.16, mean 0.22,
p90 0.44, max 0.88 mIoU (frost sev5). Release file kept as `csc_v2_gate_h200_release_on_v100.json`.

**Luminance correlate: direction fixed before computing (2026-10-19 ~04:10).** Per ACDC val image with ≥1% GT-sky and ≥1%
GT-building pixels: contrast = |mean luminance(GT sky) − mean luminance(GT building)| (Rec.601 Y, full-resolution image and labels).
Outcome = that image's sky-IoU change (adapted − same-pool vanilla). Prediction under the grey-on-grey account: Spearman
ρ(contrast, Δ sky IoU) > 0 (lower contrast → larger loss). Primary: PDA@1 on ACDC fog. Also reported: PDA@10 and TENT@10,
and ACDC rain/snow. Night is excluded from the primary because vanilla already merges sky into building there.

## Addendum (2026-10-19 05:20 EDT, cluster clock): BN-statistics control for PDA's one-step regime — registered BEFORE any such run

**Motivation (observed, in analysis_notes.md).** PDA's one-step result is flat across a 10× learning-rate range (v2, H200:
synthetic benefit +4.07 / +4.03 / +4.02 and real +0.35 / +0.32 / +0.31 at lr 1e-3 / 3e-4 / 1e-4; shortfall −5.38 / −5.39 / −5.39).
Hypothesis H_BN: at one step, PDA's effect comes mostly from BatchNorm running statistics refreshed by the train-mode
adaptation forward passes (and read by the eval-mode clean pass), not from the affine gradient step.

**Control (stats-only).** PDA at one step with the parameter update disabled: `--use_pda --K 4 --clean_final --n_adapt_steps 1
--lr_pda 0`. Everything else is identical to the registered PDA runs: checkpoint, bn affine, K=4, texture threshold 0.45,
bs 2, seed 0, crop 512×1024. The K perturbed forward passes still run in train mode, so BN running statistics update with
the same momentum as in PDA@1, but no parameter changes. Same population (95 Cityscapes-C v2 conditions, 7 real adverse,
BDD-clear probe reported separately), same GPU class as the PDA curve (H200), and benefit against the same-pool (H200)
vanilla. Before scoring, a sanity check confirms that the affine parameters after adaptation are bit-identical to the
checkpoint's (otherwise lr 0 is not a stats-only control and the run is void).

**Test statistics.** (i) R_syn = mean synthetic benefit(stats-only) / mean synthetic benefit(PDA@1, lr 1e-3) = x / 4.07.
(ii) Δ_short = shortfall(stats-only) − shortfall(PDA@1) = y − (−5.38), with the synthetic trend refit on the stats-only grid,
exactly as for every other setting.

**Prediction (H_BN supported iff BOTH hold):**
- **P7a:** R_syn ≥ 0.80, i.e. the stats-only pass recovers at least 80% of PDA@1's synthetic benefit (x ≥ +3.26).
- **P7b:** |Δ_short| ≤ 1.0 mIoU, i.e. the stats-only real shortfall lies in [−6.38, −4.38].

**Decision.** Both hold → "PDA's one-step regime is dominated by BN-statistic recalibration", tying it to the DUA/saturation
results. Either fails → reported as not supported; the one-step effect then needs the gradient step, and the LR
insensitivity stays an observation. Either way it is reported, with its paired joint-bootstrap CI (B=2000, the same method
as the step curve), and no other variants (other K, other methods) are added to this registration.

**Timing.** Not run before the workshop submission. Run afterwards on the same pipeline, so the camera-ready inherits a
result registered here first. (Implementation note, pre-run: with `--lr_pda 0` the Adam step is a no-op, so parameters do not
move; the bit-identity check above guards this.)
